SECTION 01 · PROBLEM FORMULATION

The Question: Finite Compute vs. Theoretical Infinite Regimes

In academic literature, Hyperparameter Optimization (HPO) benchmarking is frequently evaluated under the assumption of infinite sequential sampling or purely synthetic search spaces. However, when an engineering team or academic group holds a strict allocation of GPU-hours on shared supercomputing infrastructure (such as Poznań Supercomputing and Networking Center's Eagle cluster), sequential evaluation is economically untenable.

The empirical challenge reduces to: When running 40 asynchronous distributed worker processes bounded by a fixed grant ceiling, does sophisticated Bayesian conditioning (TPE, Gaussian Processes) yield superior Pareto-efficiency compared to aggressive early-pruning multi-fidelity schedules (Hyperband / ASHA)?

SECTION 02 · COMPUTATIONAL ECONOMICS

Why It Matters: The Carbon & Dollar Ledger of Modern Tuning

Modern deep learning literature rarely itemizes the graveyard of unpruned exploratory runs. Consider a modest tuning experiment: 1,000 trials of an image classification architecture trained for 90 epochs.

Unpruned Random Tuning
144 GPU-Hours

Full-epoch evaluations on unviable architectural configurations.

Budget-Aware ASHA / Hyperband
50.2 GPU-Hours

Geometric halving halts uncompetitive seeds before epoch 10.

The resulting 65% reduction in total compute time directly determines whether a lab can afford thorough seed validation before publication or whether results remain fragile single-seed artifacts.

SECTION 03 · DISTRIBUTED METHODOLOGY

Methodology: 4 Concurrent Strategies Across 40 Accelerators

Using a unified ResNet-18 proxy training harness over CIFAR-10, four optimization strategies were subjected to identical search spaces: learning rate (log-uniform 1e-4 to 1e-1), weight decay (log-uniform 1e-6 to 1e-2), optimizer choice (SGD with momentum vs AdamW), and batch size {32, 64, 128, 256}.

Strategy Type Mean GPU-h Top-1 Acc
Hyperband (ASHA) Multi-fidelity early stopping 0.050h 84.4%
TPE (Tree Parzen) Kernel density estimation 0.077h 82.0%
Random Search Uniform stochastic baseline 0.144h 61.3%
CMA-ES Covariance matrix adaptation 0.047h 44.1%

CMA-ES showed early premature convergence in discrete subspaces, yielding low wall-clock usage but poor validation accuracy. Hyperband balanced fast elimination of inferior regions with sufficient compute dedication to top-bracket models.

SECTION 05 · SYSTEMS POST-MORTEM

Engineering Note: The 40-Worker SQLite NFS Race Condition

When dispatching 40 workers simultaneously against a central SQLite database stored on an NFS/Lustre volume, Optuna's default SQLite locking mechanism crashed worker processes within 180 seconds due to file lock latency.

close Naive Startup (Crash) 
# Naive concurrent access:
study = optuna.load_study(
  study_name="cifar_hpo",
  storage="sqlite:////lustre/hpo.db"
)
# Result: OperationalError: 
# database is locked (NFS latency)
check_circle WAL Mode + Jitter (Zero Retries) 
# PRAGMA journal_mode=WAL;
# Exponential jittered retry
time.sleep(random.uniform(0.1, 0.4) 
           * (worker_id % 5))
storage = RDBStorage(
  url="sqlite:////lustre/hpo.db",
  heartbeat_interval=60
)

Furthermore, we employed Optuna's Constant-Liar parallelization heuristic for TPE to prevent workers from clustering in duplicate parameter coordinates during pending evaluations.

SECTION 06 · HONEST SCHOLARLY BOUNDARIES

What This Study Does Not Show

balance

Single Proxy Architecture (ResNet-18)

Results may not uniformly transfer to modern 7B+ decoder-only transformers where memory bandwidth, not epoch progression, governs throughput.

hourglass_empty

Queue Wait-Time Excluded

SLURM job queue latency fluctuates depending on cluster occupancy; only raw active GPU execution wall-clock time was metered in Pareto metrics.

hub

Zero SaaS / Cloud Dependencies

All coordination was intentionally kept fully on-premises without proprietary SaaS trackers (Weights & Biases, Neptune) to preserve offline computational reproduciblity.

SECTION 07 · REPRODUCIBILITY RECIPE

Reproduce It in 1 Command

Submit the self-contained SLURM array script directly on any SLURM-managed compute cluster equipped with Singularity or Apptainer:

submit_slurm_hpo.sh 
# Dispatch 40 concurrent workers under TPE with constant-liar:
sbatch --array=1-40%40 hpo_v2.slurm tpe cifar10 40

# Or trigger multi-fidelity Hyperband (ASHA):
sbatch --array=1-40%40 hpo_v2.slurm hyperband cifar10 40
