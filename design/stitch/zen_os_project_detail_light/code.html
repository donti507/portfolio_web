01 Theoretical Background

The Premise: Why Probabilistic Agents Cause Friction

Modern large language models are inherently probabilistic text generators. When deployed as "autonomous assistants," their tool invocation manifests introduce substantial anxiety into user executive planning. Users find themselves second-guessing whether an ambiguous instruction—such as "push my Friday agenda by two hours"—silently deleted an appointment or collided with an immutable deadline.

ZEN_OS solves this through transactional grounding. Every tool exposed to the assistant Dante is framed as a deterministic, provable database lease. The language model proposes candidate parameters, but a strict transactional verifier validates invariants before any mutating SQL statement executes.

03 Safety Mechanics

How Dante Stays Safe & Predictable

1

Supabase Auth & Row-Level Security (RLS)

Every SQL query initiated by Dante runs through an authenticated JWT session bound to the user's specific auth.uid(). The assistant possesses no god-mode API keys or database superuser privileges.

2

Zero Client-Side Secret Leakage

LLM provider keys (OpenAI / Gemini) remain strictly in memory within the secure Node gateway runtime. Browser bundles contain only client-scoped Supabase anonymous keys, entirely neutralizing client-side extraction attacks.

3

Explicit Reversible Transactions & Audit Logs

Before committing a mutation, Dante creates a snapshot record in an append-only audit_actions table with inverse parameters, empowering the user to execute single-click rollbacks for any agent intervention.

05 Technical Boundaries

Known Limitations

info

Web Speech API Platform Variance: Audio recognition accuracy depends strictly on host browser implementation. Chrome and Edge route audio through proprietary cloud speech engines, whereas Safari handles synthesis locally on Apple Neural Engines.

offline_bolt

Offline Horizon: Local IndexedDB cache stores a sliding window of 30 days of calendar events and tasks. Assistant actions taken while entirely disconnected from the Supabase WebSocket queue into an ephemeral reconciliation buffer.

06 Deployment Manual

Reproduce & Run Locally

Deploy the entire containerized stack including the Supabase local emulator and Vite dev server:

BASH ENVIRONMENT 
# Clone repository
git clone https://github.com/ali-yad/zen-os.git && cd zen-os

# Configure environment secrets
cp .env.example .env.local
# (Inject SUPABASE_URL, OPENAI_API_KEY)

# Spin up local database and frontend engine
npm install
npm run supabase:start
npm run dev -- --host
